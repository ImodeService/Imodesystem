# QC & R&D

โมดูลควบคุมคุณภาพและวิจัยพัฒนา (ไอคอน "QC & R&D" บนหน้าเลือกโมดูล)

ใบ QC เครื่องจักร ย้ายออกมาจาก Service เมื่อ 2026-10-16 (ประเภท, Checklist 12 ข้อ, รูป/วิดีโอ, เอกสารไทย A4 2 หน้า)

## ฐานข้อมูล

รัน `supabase/02-qc-core.sql` หนึ่งครั้งใน Supabase SQL Editor (รวมทุกอย่างของ `01-qc-records.sql` แล้ว ไม่ต้องรัน 01 รันซ้ำได้)
ถ้ายังไม่รัน หน้านี้จะขึ้นแถบเตือนบอกชื่อไฟล์ และใช้ใบ QC แบบเดิมได้อย่างเดียว

## ระยะ 1 "QC Core" (2026-10-27)

- **รับเครื่องเข้า QC**: ลงทะเบียนเครื่องใหม่ในตาราง `machines` ตัวเดียวกับ Service ออกเลข IMODE S/N `IMD-M-YY-NNNN` จากเซิร์ฟเวอร์ และเปิดงานตรวจ ในคำสั่งเดียว (`qc_intake`) พิมพ์ PO / ผู้ขาย / โครงการเองไปก่อน
- เครื่องที่ยังอยู่ใน QC (`machines.lifecycle` = `qc` หรือ `ready`) **ไม่แสดง** ในหน้าเครื่องจักรของ Service (Service js/148) จนกว่าจะกด **ส่งมอบให้ลูกค้า** (`qc_handover` ทำได้เมื่อ QC ล่าสุด "ผ่าน" เท่านั้น) แล้ว Service ดูแลเครื่องเดิมต่อ ประวัติ QC ยังผูกกับเครื่อง
- ฟอร์มตรวจเป็นขั้น: ข้อมูลงาน, รูปบังคับ 7 มุม, Checklist (ค่าที่วัด / ค่ามาตรฐาน / หมายเหตุ ระบบลงชื่อผู้ตรวจและเวลาให้ทุกข้อ), หลักฐานเพิ่มเติม, สรุปผล
- **ผ่าน** ได้เมื่อ ตรวจครบ 12 ข้อ ไม่มีข้อไม่ผ่าน ข้อ N/A มีเหตุผล และ (ตรวจรับเข้า / ตรวจก่อนส่งมอบ) มีรูปบังคับครบ 7 รูป
- **ผ่านแบบมีเงื่อนไข ไม่นับเป็นผ่าน** ส่งมอบไม่ได้
- รูปและไฟล์ใหม่เก็บใน Storage bucket `qc-evidence` (ส่วนตัว เปิดผ่านลิงก์ชั่วคราว 1 ชั่วโมง) ตาราง `qc_evidence` รูป base64 ของ QC เก่ายังแสดงเหมือนเดิม
- แท็บ **เครื่อง (IMODE S/N)** ค้นหาด้วย IMODE S/N, Factory S/N, PO, โครงการ, ผู้ขาย หรือลูกค้า แตะเครื่องเพื่อดูประวัติ QC และส่งมอบ
- สิทธิ์ตอนนี้: พนักงานที่ล็อกอินอ่าน/เพิ่ม/แก้ได้ ลบได้เฉพาะแอดมิน (บังคับใน RLS) แยกสาย QC Admin / Head / Technician เป็นระยะ 2

## V3.1 ระยะ 1 "Head QC อนุมัติ" (2026-11-07)

ต้องรัน `supabase/03-qc-roles-audit.sql` และ `04-qc-approval.sql` (หลัง 02) ถ้ายังไม่รัน หน้านี้ทำงานแบบระยะ 1 เดิมและขึ้นแถบบอกชื่อไฟล์

- ช่างเลือก "ผ่าน" / "ผ่านแบบมีเงื่อนไข" เองไม่ได้แล้ว สถานะในฟอร์มมีแค่ รอตรวจ / กำลังตรวจ / ไม่ผ่าน และปุ่ม **ส่งให้ Head QC อนุมัติ** (กดได้เมื่อด่านครบ ระบบตรวจซ้ำฝั่งฐานข้อมูลด้วย `qc_submit`)
- แท็บ **รออนุมัติ** (ตัวเลขบนแท็บ = จำนวนรอ): คิวเรียงตามเวลาส่ง กดแล้วเห็นข้อมูลเครื่อง ด่านตรวจจาก `qc_gate` รูปบังคับ 7 รูป ประวัติ แล้ว Head QC กด **อนุมัติ QC PASS** / **ส่งกลับแก้ไข** / **ไม่อนุมัติ (ไม่ผ่าน)** (สองอย่างหลังต้องใส่เหตุผล) ผ่าน `qc_decide`
- ผู้ตรวจหรือผู้ส่งใบนั้นอนุมัติเองไม่ได้ (ทั้งหน้าเว็บและฐานข้อมูล) ต้องเป็น Head QC อีกคน
- ใบที่รออนุมัติ / อนุมัติแล้ว / ยกเลิก แก้ไขไม่ได้ ใบที่ถูกส่งกลับแสดงเหตุผลด้านบนฟอร์ม
- Head QC เปิดแก้ใบที่อนุมัติแล้วได้ (ใส่เหตุผล, Revision +1, เครื่องกลับเป็นอยู่ระหว่าง QC) ถ้ายังไม่ส่งมอบ; Head QC / Admin QC ยกเลิกใบที่ยังไม่อนุมัติได้แทนการลบ
- เครื่องเป็น "ผ่าน QC รอส่งมอบ" (`ready`) หลัง Head QC อนุมัติเท่านั้น ส่งมอบได้เฉพาะใบที่อนุมัติแล้ว
- เอกสาร QC แสดงผู้อนุมัติและวันที่จากการอนุมัติจริง และมี "ประวัติการอนุมัติ" ด้านบน
- บทบาทอ่านจาก `profiles.role` / `extra_roles` ผ่าน `qc_my_roles()` (เช่น `Head QC`, `Admin QC`, `QC Technician`)
- เปิดจาก Service ได้อีกครั้ง (ที่ประชุม 2026-11-03): เมนูด้านข้างแสดง Service แล้ว และถ้าเปิดมาด้วย `?case=` หรือ `?from=service` จะมีปุ่ม **กลับไป Service**

## V3.1 ระยะ 2 "PO · รับเข้า Stock · NCR · ส่งมอบ" (2026-11-07)

ต้องรัน `supabase/05-qc-ncr.sql` → `06-qc-po-stock.sql` → `07-qc-release.sql` (หลัง 04) แต่ละไฟล์เปิดส่วนของตัวเอง ถ้ายังไม่รัน แท็บนั้นจะไม่แสดง
Stock และจัดซื้อยังไม่ใช้ระบบ: ทีม QC บันทึกแทน ทุกจุดต้องใส่ **ชื่อคนที่ทำจริง** และระบบเก็บชื่อผู้บันทึกแทนไว้ด้วย

- **PO / อุปกรณ์ค้าง** (STEP 01): เปิด PO แทนจัดซื้อ (เลข PO, ผู้ขาย, รายการเครื่อง, ชื่อผู้จัดซื้อ) และรายการอุปกรณ์ค้างส่งรายชิ้น: บันทึกการติดตาม เลื่อนกำหนด ได้รับแล้ว ยกเลิก ได้รับครบทุกชิ้นแล้วใบ QC เป็นอุปกรณ์ "ส่งครบแล้ว"
- **รับเครื่องเข้า QC** (STEP 02): เลือก PO แล้วกรอกข้อมูลเครื่องให้ ใส่ชื่อคน Stock ที่รับ วันเวลา ที่เก็บ สภาพตอนรับ และอุปกรณ์ที่ขาดทีละชิ้น ทั้งหมดบันทึกในคำสั่งเดียว `qc_receive` ได้ใบรับ RCV-ปปปป-NNNN
- **NCR** (STEP 04): ข้อ Checklist ที่ "ไม่ผ่าน" มีปุ่ม **เปิด NCR ข้อนี้** (บันทึกใบ QC ก่อน) → รูปก่อนแก้ + สาเหตุ + แผน → Head QC อนุมัติแผน (คนเสนอแผนอนุมัติเองไม่ได้) → แก้ไข + รูปหลังแก้ → Re-QC → Head QC ปิด NCR แล้วข้อนั้นเป็น "ผ่าน" ใบ QC กลับเป็น "กำลังตรวจ" ให้ส่งอนุมัติ ระหว่างมี NCR ค้างส่งอนุมัติ/ปล่อยเครื่องไม่ได้
- **ส่งมอบ** (STEP 06): เครื่องที่ Head QC อนุมัติแล้ว → วางแผนส่ง (ลูกค้า, ส่งตรงหรือผ่าน Stock, ชื่อจัดซื้อที่อนุมัติแผน) → Head QC ยืนยัน Release → (Stock รับ) → ส่งมอบพร้อมรูปลายเซ็นผู้รับ แล้วเครื่องไปอยู่ที่ Service ปุ่ม "ส่งมอบให้ลูกค้า" แบบเดิมใช้ไม่ได้เมื่อเปิด `release_required`
- หน้าเครื่องแสดงใบรับเข้า Stock อุปกรณ์ค้าง และประวัติการส่งมอบ
